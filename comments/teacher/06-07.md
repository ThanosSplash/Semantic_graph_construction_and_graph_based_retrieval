# Οδηγίες επόμενης φάσης για την πτυχιακή

Η υλοποίηση έχει πλέον προχωρήσει αρκετά. Υπάρχει cosine baseline, υπάρχουν semantic graphs πάνω στα passages, υπάρχει Personalized PageRank, k-step neighborhood expansion, graph-aware reranking, BM25/cross-encoder ως πρόσθετοι rerankers, query sampling και leaderboard/output structure.

Από εδώ και πέρα ο στόχος **δεν** είναι να προσθέτεις συνεχώς νέες μεθόδους. Ο στόχος είναι να σταθεροποιήσεις την ορθότητα της υλοποίησης και μετά να κάνεις **βαθιά πειραματική μελέτη** πάνω σε λίγες βασικές μεθόδους.

Η βασική μέθοδος στην οποία πρέπει να εμβαθύνεις είναι:

```text
Personalized PageRank + cosine fusion
```

Το k-step neighborhood expansion θα λειτουργήσει ως δεύτερη βασική graph-based μέθοδος. Τα BM25, HITS, shortest path και cross-encoder να μείνουν ως επιπλέον / βοηθητικά πειράματα, όχι ως κύριος κορμός της πτυχιακής.

# 2. Άμεσες διορθώσεις πριν τα τελικά πειράματα

## 2.1 Διόρθωσε το nDCG@K

Η τωρινή χειροκίνητη υλοποίηση είναι καλύτερη από την προηγούμενη χρήση της `sklearn.ndcg_score`, αλλά πρέπει το `IDCG` να βασίζεται στο πλήθος των συνολικά relevant documents μέχρι το `K`.

Η ασφαλής λογική είναι:

```python
def ndcg_at_k(predictions, ground_truth, k):
    import numpy as np

    correct_set = set(ground_truth)

    rel = np.array([
        1 if doc_id in correct_set else 0
        for doc_id in predictions[:k]
    ])

    dcg = sum(
        rel[i] / np.log2(i + 2)
        for i in range(len(rel))
    )

    ideal_len = min(len(correct_set), k)
    ideal_rel = np.ones(ideal_len)

    idcg = sum(
        ideal_rel[i] / np.log2(i + 2)
        for i in range(ideal_len)
    )

    if idcg == 0:
        return 0.0

    return dcg / idcg
```

Γιατί είναι σημαντικό:

```text
Αν υπάρχουν 3 relevant passages αλλά το σύστημα βρει μόνο 1,
το nDCG δεν πρέπει να συμπεριφέρεται σαν να βρήκε όλα τα relevant.
```

## 2.4 Έλεγξε safety checks στο PPR

Στο Personalized PageRank πρέπει να έχεις προστασία για τις περιπτώσεις:

```text

```

Η λογική πρέπει να είναι περίπου:

```python
valid = [
    (node_id, sims[i])
    for i, node_id in enumerate(init_nodes)
    if node_id in node_to_idx
]

total = sum(score for _, score in valid)

if total == 0 or len(valid) == 0:
    return []
```

Μην αφήσεις το PPR να τρέχει με άδειο ή μηδενικό personalization vector.

# 3. Κύρια μέθοδος εμβάθυνσης: Personalized PageRank + Fusion

Η βασική εμβάθυνση της πτυχιακής πρέπει να γίνει στο:

```text
Personalized PageRank με cosine fusion
```

Αυτό ταιριάζει περισσότερο με τον τίτλο της πτυχιακής, γιατί είναι καθαρά graph-based retrieval χωρίς GNNs.

## 3.1 Τελική μορφή PPR retrieval

Η λογική πρέπει να είναι:

```text
1. Για κάθε query, υπολόγισε cosine similarity με όλα τα passages.
2. Πάρε top-init passages ως seed nodes.
3. Φτιάξε personalization vector από τα cosine scores των seed nodes.
4. Τρέξε Personalized PageRank πάνω στον semantic graph.
5. Πάρε PPR score για όλα τα graph nodes.
6. Συνδύασε PPR score με cosine score.
7. Κάνε τελικό ranking.
```

## 3.2 Fusion score

Το βασικό scoring πρέπει να είναι:

```text
final_score = alpha * cosine_score + (1 - alpha) * PPR_score
```

Δοκίμασε:

```text
alpha = 0.0, 0.2, 0.5, 0.8, 1.0
```

Ερμηνεία:

```text
alpha = 1.0 → καθαρό cosine baseline
alpha = 0.0 → καθαρό graph/PPR score
alpha ενδιάμεσο → graph-enhanced retrieval
```

Αυτό είναι πολύ σημαντικό, γιατί θα δείξει αν ο γράφος βοηθά μόνος του ή αν βοηθά καλύτερα ως συμπλήρωμα του cosine retrieval.

## 3.3 Seed-size sensitivity

Δοκίμασε διαφορετικό αριθμό seed documents:

```text
init = 5, 10, 20, 50
```

Ερώτηση που απαντάς:

```text
Πόσα αρχικά cosine documents χρειάζονται ώστε το PPR να κάνει χρήσιμη propagation;
```

## 3.4 Graph-type sensitivity

Τρέξε PPR πάνω σε διαφορετικούς τύπους γράφων:

```text
kNN-5
kNN-10
kNN-20

Mutual-kNN-5
Mutual-kNN-10
Mutual-kNN-20

Threshold-0.3
Threshold-0.4
Threshold-0.5
Threshold-0.6

Cluster-kNN-10
Cluster-mutual-kNN-10
```

Ερώτηση που απαντάς:

```text
Ποια κατασκευή γράφου δίνει καλύτερη δομή για propagation;
```

## 3.5 Weighted vs unweighted ablation

Αργότερα, αφού βγουν τα πρώτα αποτελέσματα, τρέξε:

```text
Weighted graph:
edge weight = similarity

Unweighted graph:
edge weight = 1
```

Ερώτηση που απαντάς:

```text
Βοηθάει πραγματικά το similarity weight ή αρκεί μόνο η γειτονιά;
```

# 4. Δεύτερη βασική μέθοδος: k-step neighborhood expansion

Το k-step να μείνει ως δεύτερη βασική μέθοδος, αλλά όχι να ξεπεράσει σε προτεραιότητα το PPR.

## 4.1 Τελική μορφή k-step

Η λογική είναι:

```text
1. Πάρε top-init documents από cosine.
2. Επέκτεινε στον γράφο για 1, 2 ή 3 hops.
3. Πάρε τα candidate nodes που βρέθηκαν.
4. Κάνε reranking με:
   - graph_aware
   - BM25
   - cross_encoder μόνο ως extra
```

## 4.2 Πρώτα πειράματα k-step

Τρέξε μόνο στους καλύτερους 2–3 graphs από το PPR stage.

Παράδειγμα:

```text
graph = kNN-10, mutual-kNN-10, threshold-0.4
hops = 1, 2, 3
init = 5, 10, 20
alpha = 0.2, 0.5, 0.8
reranker = graph_aware
```

Μετά, αν υπάρχει χρόνος:

```text
reranker = BM25
reranker = cross_encoder
```

Το cross-encoder να μείνει extra / upper-bound, όχι βασική μέθοδος.
